# Positioning readiness rubric

Open this in procedure step 8: to grade the document, to write the questions for the user, and
to fold their answers in.

## Grading

Give every criterion a verdict. A guess never beats an honest gap.

- **met** (1.0): fully satisfied by concrete content the company stands behind.
- **partial** (0.5): present but vague, generic or half done.
- **unmet** (0): absent, or still template.

What counts:

- Guidance text, examples and gap markers are unmet. An untouched template scores close to 0.
- The user's own words count, cited or not.
- Anything labelled inferred is partial at most. A label under a heading covers the whole section.
- A cited public fact the company states about itself (its category, named customers, stated differentiators) is met.
- Whole-document checks are unmet while the sections they reason over are empty.

Score each group: `10 x sum(weight x verdict) / sum(weights)`. The document score is the
weighted average of the group scores, using the group weights below. Bands: Thin below 4,
Workable 4 to below 7.5, Strong 7.5 and up. A website-only capture is a starting hypothesis; the
score climbs as the user confirms inferences and supplies the alternatives buyers really weigh,
what only they can claim, and hard proof.

## Criteria

| Group (weight) | Criterion | Weight |
| --- | --- | --- |
| Positioning Statement (5) | Filled with a concrete target customer, category, key benefit and primary alternative | 2 |
| | States one most important benefit, not a list of everything the product does | 2 |
| | Names the core differentiation the primary alternative cannot match, specifically | 2 |
| Market Category (3) | Names the concrete category claimed | 2 |
| | States why this frame beats the obvious alternative framing | 1 |
| Competitive Alternatives (4) | Two or more concrete real alternatives (status quo, point tool, incumbent, native option) | 2 |
| | Each states the specific reason a buyer would pick it instead | 2 |
| Unique Attributes (5) | Three or more concrete capabilities the alternatives lack | 3 |
| | Each is genuinely differentiating, not table stakes | 2 |
| Value Themes (5) | Each attribute maps to the concrete benefit the customer gets | 3 |
| | Each theme names the role or buyer who cares most | 2 |
| Best-Fit Customer (4) | Names the segments where value is sharpest, consistent with the ICP | 2 |
| | States the size or org signal that means a buyer and budget exist | 1 |
| | Names the trigger that forces a best-fit buyer to act now | 1 |
| Market Trends (2) | At least one concrete shift that makes the value timely | 2 |
| | Trends are grounded in cited evidence | 1 |
| Proof Points (5) | Two or more concrete proof points (benchmark, ROI study, analyst standing, named customer, outcome metric) | 3 |
| | Each is tied to the claim it substantiates and is fact-based, not aspirational | 2 |
| Whole document (4) | The statement's differentiation is backed by at least one unique attribute and one proof point | 3 |
| | Every value theme traces to a listed unique attribute | 2 |
| | Best-fit traits do not contradict the segments in the statement | 2 |
| | Claims that need evidence carry a proof point; unsupported superlatives are flagged | 2 |
| | Attributes, alternatives and proof rest on real product, competitive or customer evidence, not only website inference | 3 |

For every criterion not met, note how it closes: an answer from the user (the default, and always
for contradictions, unsupported claims and inferences to confirm), a document they could attach
(a deck, competitive notes, a case study), a number from a connected system (win rates, deal
counts), or a public web search.

## Questions for the user

Ask only what all four are true of: nothing already read answers it; it belongs in positioning
(alternatives, category, unique attributes, proof and results, why now; not company size or
personas, which belong to the ICP and persona work); the answer would materially move the
document; only the company can tell you.

- If something already read answers part of the gap, ask only for the rest and say what you have: "Your deck names mid-market SaaS as the core buyer. Is there a size below which you stop pursuing deals?"
- Confirm an inference only when its section matters: "We have the bundled status page as what buyers use instead of you. Is that right, or what else do they compare you with?"
- Ask for facts the user knows, never for the modelling. No scores, weights, sections or "your positioning document". Never ask them to write the document (no "what is your tagline").
- Self-contained: the user sees the question alone. Name the thing inline.
- One fact per question, one or two sentences, at most 35 words, plain words, no dashes.
- At most five questions, heaviest gap first: an empty core section before a weak detail.

## Folding answers in

The answer is source material, not copy. Take the fact out and write it the way the document is
written.

- Third person, declarative, present tense. No "we", "I would say", hedges or intensifiers ("could be", "definitely", "at the moment"). Never restate the question.
- One fact per cell or bullet, in the shortest form that carries it.
- Change only the cell, row or bullet the answer addresses. Re-emit everything else in the section exactly, citations included. An answer silent about existing content does not contradict it.
- Keep the section's shape: a table stays a table with the same columns, bullets keep their bold leads.
- Write only what the user said. "We mostly displace spreadsheets" updates Competitive Alternatives; it does not license a new category frame or proof points.
- "We don't have that yet" is an answer: record `_Not tracked yet (per <role>, <date>)._` so the question is not asked again.
- An empty, skipped or off-topic answer adds nothing.

Example. The answer "Rising support costs could be one, because we actually let them skip writing the same email three times" becomes `**_Trend:_** Rising support costs: one update replaces three hand-written messages per incident.`
