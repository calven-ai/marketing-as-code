# G2 (source token `g2`; categories `surveys-reviews`, `intent`)

Routes (from `integrations/catalog/surveys-reviews.json`): the remote MCP
server `g2` (OAuth with a G2 Seller Solutions login, a person in a
session). No CLI, no script route, so G2 pulls never run unattended;
schedule the export instead. The server is read-only. Buyer intent needs a
plan that includes it; reviews and the catalog are available more widely.

## Calls per snapshot

Tool names: check the tool list in the session (reviews for a product,
product and category lookups, buyer intent signals). Ask for the product
id first when the team has more than one listing.

| `<what>` | Call |
| --- | --- |
| reviews | reviews for the product, filtered to the period (or all when the folder has no earlier snapshot), one row per review |
| intent (ad hoc, private repo only) | buyer intent signals for the period, one row per account and signal; saved under `data/accounts/snapshots/YYYY-MM-DD-g2-intent.csv` |

## Mapping to the snapshot columns

`review_id` = the review's id; `date` = submitted date; `rating` = the
star rating (1 to 5, decimals allowed); `role` = the reviewer's role or
title as G2 categorises it; `company_size` = G2's size bucket; `title`,
`pros`, `cons` = the review's own fields. Reviewer names, emails and
LinkedIn URLs never enter the snapshot; quote a verbatim by role and
size only (`data/reviews/README.md`).

## Limits and cost

- Reviews arrive a page at a time; page to the end and count against
  the total the product page shows.
- Rate limits follow the plan; a monthly reviews pull is a few calls.
- Cost: included in Seller Solutions; intent data is a paid add-on.

## Export fallback

G2 Seller Solutions > Reviews > Export (CSV), all reviews or the period.
Drop at `data/reviews/snapshots/YYYY-MM-DD-g2-reviews.csv`, delete the
reviewer name and contact columns before committing, and rename the rest
to the snapshot set.
