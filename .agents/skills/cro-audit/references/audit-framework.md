# The audit framework

Condensed from the CRO skill above: seven factors in impact order, the
questions to ask first, page-type checks, and the recommendation groups.

## Ask before auditing

1. Current conversion rate and the target (or "unknown", which is an
   answer).
2. Traffic sources and volumes; the promise each source made.
3. What happens after this page (the next step in
   `data/ontology/funnel.md`).
4. What evidence exists: funnel, heatmaps, recordings, user research.
5. What was tried before and what happened.

## Seven factors, in impact order

| Factor | The question | Evidence |
| --- | --- | --- |
| Value proposition | does a first-time visitor know what this is, for whom, and why, in five seconds | headline and subheadline read cold |
| Message match | does the page keep the promise of the ad, email or search result | the ad brief, the query, the UTM source |
| CTA | is the primary action visible, first, and worded as what they get | position, count, wording, contrast |
| Hierarchy and scannability | can a scanner get the argument from headings alone | headings read in order |
| Proof | is credible evidence next to each decision point | logos, numbers, quotes with names |
| Objections | are cost, setup, fit, security and "does it work" answered | FAQ, comparison, guarantee |
| Friction | form length, mobile layout, speed, unclear next step | field count, device split, LCP |

Score each 1 to 5 with the evidence line; the funnel says where people
leave, the factors say why.

## Page-type checks

- **Landing (paid)**: one CTA, message match, navigation removed or
  minimal, the whole argument on one page.
- **Homepage**: clear to a cold visitor; two paths (ready to buy, still
  researching); one prominent conversion route.
- **Pricing**: plans comparable at a glance, a recommended tier, the
  "which one is for me" anxiety answered, the next step for each plan.
- **Feature page**: feature tied to a benefit, a use case, a clear try or
  buy path.
- **Signup or form flow**: fields the team uses, labels above fields,
  inline validation, progress shown, autofill and the right mobile input
  types.

## Common conversion killers

Features where benefits belong; a generic value statement; "Submit" and
"Learn more"; no proof near the CTA; too many fields; navigation that
leaks; a mobile layout nobody checked.

## Recommendation groups

- Quick wins: low effort, immediate (copy, CTA wording, field removal).
- High-impact changes: real effort, large expected lift (structure,
  offer, flow).
- Tests: hypotheses for `ab-test-plan`, one variable each.
- Copy alternatives: two or three headlines or CTAs with the reasoning,
  for `landing-page` to take up.
