# Case study shapes and the approval checklist

Written for this repo from common practice.

## Full study, 600 to 1,200 words

1. Title: "[Customer] achieves [result] with [product]". Only when the
   result is a verified number; otherwise "[Customer] on [the change]".
2. Snapshot box: industry, size, region, the product or plan, the one
   key result, the timeframe.
3. Challenge: the situation before, in the customer's words; what it
   cost them in time, money or risk; what they tried first.
4. Solution: why they chose us (their words), what they set up, how
   long it took, who was involved. No feature list; the parts of the
   product that mattered to this story.
5. Results: two to four numbers with the baseline, the period and the
   source; one line each on what the number means for the persona.
6. Quote: one strong verbatim quote, attributed as approved.
7. What is next: one paragraph on where they are going.
8. CTA: one, from the brief.

## Spotlight, 200 to 400 words

Snapshot box, one paragraph of challenge, one of solution, one result,
one quote, the CTA. Built for a landing page tile or a sales deck slide.

## Quote pack

Five to ten quotes, each with: the verbatim line, who said it and the
attribution allowed, one sentence of context, the theme it proves
(pillar or objection), and where it fits (website, deck, social, sales
email). Sorted by theme. Unapproved quotes sit in a separate section
headed "Awaiting approval".

## What makes a quote usable

Specific (a number, a before and after, a named task), in the speaker's
own register, short enough to read on a slide, and free of a claim
about a competitor. "Great tool, love it" is not a quote; "we stopped
rebuilding the report every Monday" is.

## Numbers

| Kind | Where it must come from | How it appears |
| --- | --- | --- |
| Customer's own result | the transcript, line referenced | "Acme reports ..." until approved |
| Our measured number | a snapshot path under `data/` | the number, the period, the path in Data used |
| Anything else | nowhere yet | "to confirm" in the checklist, absent from the draft |

Never round up, never annualise a monthly figure without saying so,
never compare to a baseline the customer did not give.

## Approval checklist

| Item | Detail | Attribution | Source | Approved by | Date |
| --- | --- | --- | --- | --- | --- |
| Quote 1 | verbatim text | name and role / role only / anonymous | transcript line | | |
| Number 1 | the figure and period | | snapshot path or transcript line | | |
| Logo use | website / deck / social | | | | |
| Name and title | as they wish to appear | | | | |
| Review round | customer reviewed the full draft | | | | |

A study leaves `draft` only when every row has an approver and a date.
The checklist lives at the end of the piece's `brief.md`, so the
approval travels with the piece.
