# Messaging readiness rubric

Open this in procedure step 8: to grade the framework, to write the questions for the user, and to
fold their answers in.

## Grading

Give every criterion a verdict. A guess never beats an honest gap.

- **met** (1.0): fully satisfied by concrete content the company stands behind.
- **partial** (0.5): present but vague, generic or half done.
- **unmet** (0): absent, or still template.

Guidance text and gap markers are unmet. The user's own words count, cited or not. Anything
labelled inferred is partial at most. Whole-framework checks are unmet while the sections they
reason over are empty.

Score each group: `10 x sum(weight x verdict) / sum(weights)`; the framework score is the weighted
average of the group scores. Bands: Thin below 4, Workable 4 to below 7.5, Strong 7.5 and up.

## Criteria

| Group (weight) | Criterion | Weight |
| --- | --- | --- |
| Core Narrative (5) | One concrete core message: the benefit and who it is for | 2 |
| | A one-liner that says what the product does and who relies on it, not a generic tagline | 2 |
| | The 30-second pitch frames a real problem and closes on a quantified outcome | 1 |
| Value Pillars (5) | Three load-bearing pillars, each with a headline claim | 3 |
| | Each pillar pairs its headline with concrete proof, not an empty proof cell | 2 |
| Persona Value Props (4) | Each persona's value prop is framed for what that persona cares about, not the core message restated | 2 |
| | Each names its lead pillar | 1 |
| Messaging Matrix (4) | Rows are the real primary buying roles | 2 |
| | Awareness, consideration and decision cells carry distinct stage-appropriate messages | 2 |
| Objection Handling (3) | Two or more real objections in the buyer's words | 2 |
| | Each is reframed with proof or customer evidence, not a bare assertion | 1 |
| Variations (2) | At least one priority vertical or named campaign has a specific angle and lead | 1 |
| Boilerplate (2) | Names who the company is, what it does, who relies on it, and the proof worth citing | 1 |
| Words to Use and Avoid (2) | Each entry carries a reason and a source | 1 |
| Whole framework (4) | Every pillar ladders up to the core message | 2 |
| | Proof cells trace to real proof points or customer evidence, not fabricated metrics | 3 |
| | Persona rows match the captured personas; no invented or contradictory roles | 2 |
| | Narrative and pillars agree with the positioning; contradictions are surfaced, not resolved silently | 3 |
| | Messages rest on real positioning, product or customer evidence, not only website inference | 2 |

For every criterion not met, note how it closes: an answer from the user (the default, and always
for contradictions, unsupported claims and inferences to confirm), a document they could attach
(a messaging guide, a case study, a sales deck), a number from a connected system, or a public
web search.

## Questions for the user

Ask only what all four are true of: nothing already read answers it; it belongs in messaging
(the narrative, the pillars, how objections are answered, the boilerplate; alternatives, category
and proof belong to positioning, roles and pains to personas); the answer would materially move
the framework; only the company can tell you.

- Ask for the raw fact, never for the writing. Not "what should each persona hear at each stage" or "what is your tagline", but "What does a Head of Support say on a first call that tells you they have the problem?"
- Never name the machinery: no scores, weights, sections or "your messaging document".
- Self-contained, one fact per question, one or two sentences, at most 35 words, no dashes.
- If a source answers part of the gap, ask only for the rest and say what you have.
- At most five questions, heaviest gap first.

## Folding answers in

The answer is source material, not copy. Take the fact out and write it in the framework's voice.

- Third person or the brand's own voice as the section uses it; no "I would say", hedges or intensifiers. Never restate the question.
- Change only the cell the answer addresses; re-emit everything else exactly, citations included.
- A table stays a table with the same columns.
- Write only what the user said; do not extrapolate a new pillar from one remark.
- "We don't have that yet" is an answer: record `_Not tracked yet (per <role>, <date>)._`
- An empty, skipped or off-topic answer adds nothing.
