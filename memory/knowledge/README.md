# memory/knowledge/

The living knowledge base: one topic per file, kebab-case
(`pricing-history.md`, `event-playbook.md`, `what-resonates-on-linkedin.md`).

Unlike the decision log (append-only), knowledge files are **updated in
place** as facts change — git history preserves the past. The
`chief-of-staff` skill proposes updates here from meeting transcripts, always
as a reviewable diff.

A good knowledge file states current truth, links the decisions that shaped
it (`memory/decision-log.md`), and gets pruned when it stops being true.
